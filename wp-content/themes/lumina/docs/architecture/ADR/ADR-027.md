# ADR-027 — Standalone theme: parent dependency removal

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 16 (Safe Rebranding)

## Context

Lumina shipped as a child theme with `Template: generatepress`, relying on
the parent's shell files (`header.php`, `footer.php`, `index.php`) and a
final parent fallback tier in `TemplateResolver`. Phase 16 requires a fully
standalone theme with zero detectable trace of the previous parent
relationship.

## Decision

1. **Remove `Template: generatepress`** from `style.css` — Lumina no longer
   declares a parent theme.
2. **Ship the theme shell:** original `header.php`, `footer.php`, `index.php`,
   `single.php`, `page.php`, `archive.php`, `search.php`, `404.php`,
   `comments.php`, `searchform.php` — all original markup using public
   WordPress APIs only.
3. **TemplateResolver:** drop the parent fallback tier and the `$parent_dir`
   constructor parameter; candidates resolve through
   `templates/{override}/{slug}.php` → `templates/{slug}.php` →
   `templates/wp-{slug}.php` → `null`.
4. **Region hooks:** the shell fires public `lumina_before_header` /
   `lumina_after_header` / `lumina_before_footer` / `lumina_after_footer`
   actions — the extension surface the Companion plugin fills.
5. **Integrity:** the former parent-package hash gate (473/473) is retired;
   `bin/verify-lumina-integrity.sh` hashes the shipped Lumina tree against a
   freeze baseline.

## Consequences

- The theme activates on a clean WordPress install with no parent.
- No GeneratePress or GP Premium file ships with the product; the GitHub
  monorepo packages remain only in git history.
- Functional parity with v0.14.0 is proven by the 14 smoke suites (all green
  after the change).
