# ADR-023 — Phase 12 Frontend Template Library

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 12 (Frontend Template Library)

## Context

Phase 11 delivered a 78-component library. Phase 12 turns it into complete
premium templates — the composition contract between template files and the
registry (plan §Phase 12). Every template must be assembled entirely from
reusable components: no duplicated markup, no hardcoded business logic, and
WooCommerce pages must use the Woo Bridge only (never direct `wc_` calls in
templates).

## Decision

1. **Composer:** `Templates\Composer` automaps a template slug → region →
   component sequence. `compose($slug, $data)` renders each region through
   the Phase-5 Registry — templates never contain markup, business logic, or
   WordPress/WooCommerce calls (plan §Phase 12 "each references only registry
   components").
2. **Maps:** one canonical `app/Templates/config/maps.php` covering 23 slugs
   (site shell, home/landing, commerce, blog/content, utility pages). Props
   are static arrays or lazy callables `fn(array $data): array`, so templates
   stay data-driven and WP-free CLI-verifiable.
3. **Templates:** thin files under `templates/frontend/{slug}.php`. Each is a
   WordPress template that delegates entirely to `View::compose($slug, $data)`
   with data arriving through the `lumina_template_data` filter (and the
   `lumina_template_slug` filter for custom page templates). Zero business
   logic — the map-check in smoke-phase12 asserts no `wc_*`, no
   `get_template_part` bypass, no `WP_Query` in the frontend layer.
4. **WooCommerce:** commerce templates (`shop`, `product`, `cart`, `checkout`,
   `thank-you`, `account`, `wishlist`, `compare`) reference only registry
   components; their data arrives via the Phase-9 Woo Bridge upstream. No WC
   template files are copied, no `woocommerce_*` hooks are touched.
5. **Facade:** `View::compose()` mirrors `Composer::compose()` for template
   authors (same pattern as `View::partial()`/`View::section()`).

## Consequences

- Every required Phase 12 template (home, product, collection, cart,
  checkout, thank-you, account, wishlist, compare, search, blog, single-post,
  author, archive, 404, landing, contact, about, faq, privacy, terms, custom)
  is assembled from components with no duplicated markup.
- Template output is escaped at the component leaf; WP-free smoke drives
  `compose()` for all 23 slugs without WordPress.
- Adding a template = adding a maps.php entry + a thin file (or reusing
  `custom.php`) — no new rendering code.
- WooCommerce, GeneratePress, and WordPress Core remain untouched.
