# ADR-016 — Phase 5 Component Registry

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 5 (Component Registry)

## Context

The Render Engine (Phase 4) produces HTML strings from views and data, but
there is no named, versioned, discoverable unit of presentation. The plan
(§Phase 5) mandates a central registry: registration, discovery, versioning,
dependency validation, slots, variants, composition rules, and a public
`[lumina:{slug}]` shortcode DSL — with components staying pure presentational
units that receive data through props and return strings only.

## Decision

1. **Core object:** `Components\\Registry` with `register()`, `get()`, `has()`,
   `all()`, `versions()`, `provides_slot()`, `resolve_dependencies()`,
   `render()`, `render_shortcode()`. Definitions are immutable
   `ComponentDefinition` value objects (name, renderer view slug, shortcode
   slug, prop schema, variants, slots, deps, version).
2. **Discovery:** canonical `app/Components/config/components.json` plus
   per-instance `components.json` paths from config `components.json_paths`
   (merged by `Loader`, PHP `register()` wins over JSON). `DefinitionCompiler`
   enforces the schema (name pattern `/^[a-z0-9][a-z0-9\-]{0,63}$/`, non-empty
   renderer, int version ≥ 1).
3. **Dependencies:** validated per request by `resolve_dependencies()` — the
   `CycleDetector` (DFS) throws `ComponentCycleException` on cycles and
   `ComponentException` on unregistered deps. Failures are deterministic and
   diagnosable, never silent at render time.
4. **Variants & slots:** `Resolver` merges variant presets as defaults
   (explicit props win) and materializes declared slots from child-component
   lists into trusted HTML before the renderer runs. Slot HTML is
   registry-rendered from escaped leaves — the only intentionally raw output
   path in a component template.
5. **Composition rules:** components never touch WP globals, never call WP
   functions in render scope, and compose only via props/slots. Data flows in
   through Phase-4 Data adapters upstream.
6. **Public DSL:** each component's `slug` registers as `[lumina:{slug}]`
   (e.g. `[lumina:button]`) via `ShortcodeRegistry`; `add_shortcode` is wired
   on provider boot only when WordPress is present (WP-free CLI parity via
   `Registry::render_shortcode()`). Unknown tags render empty — never throw on
   the WP surface.
7. **Container wiring:** `ComponentsServiceProvider` binds `components.registry`
   (singleton) seeded from discovery; registered in `Config\\config.php`
   `providers`, gated by `features.component_registry`.

## Consequences

- Components are discoverable, versioned, and validated before use; cycles
  and missing deps surface as clear exceptions at registration validation.
- The registry is the single gateway for `[lumina:{slug}]` authoring —
  backend content can invoke components without PHP.
- Slots keep composition declarative (child lists) while staying safe
  (children render through the same escaped pipeline).
- Registry state is pure in-memory PHP — fully testable WP-free
  (`bin/smoke-phase5.php`, 38 assertions).
