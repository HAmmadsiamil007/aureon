# ADR-021 — Phase 10 Animation Engine

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 10 (Animation Engine)

## Context

Lumina needs a declarative animation system (GSAP + Lenis smooth-scroll +
Three.js) driven by a registry, gated by performance budgets and
`prefers-reduced-motion` — with no page-specific animations, no marketing
effects, and zero cost when unused (plan §Phase 10). The Asset Pipeline
(Phase 7) supplies the build; the Design Token Engine (Phase 3) supplies
`motion.*` tokens.

## Decision

1. **Registry:** `Animation\AnimationRegistry` stores named `Preset` value
   objects (name, type, target selector, GSAP tween options, scroll options,
   decorative flag). Presets are allowlisted by name — no user string is ever
   turned into a function (no eval).
2. **Controller:** `Animation\Engine` aggregates registry + `ReducedMotion` +
   `Breaking` (budgets) + `Lenis` + `Three` + `Scroll\Trigger` into a single
   serialized boot config for the JS runtime; emits
   `lumina_core:animation:ready` (ADR-006) when active.
3. **Reduced motion:** `ReducedMotion` (config-enforced, `motion.reduced`
   token) + inline CSS guard (`animation:none !important`) + JS early exit
   before any library loads — no listeners, no observers, static content.
4. **Performance gates:** `Breaking` — 120 KB JS budget, IntersectionObserver
   cap 40, `will-change` only while animating. `Engine::is_active()` drives
   the enqueue decision: `lumina-animation` loads only when the registry is
   non-empty / lenis enabled / three mounted / triggers registered.
5. **Lazy libraries:** GSAP, Lenis, Three are **dynamic imports** in the
   `animation` Vite entry (code-split chunks, never global). Three only
   instantiates when a declared canvas mount exists in the DOM.
6. **Wiring:** `AnimationServiceProvider` binds `animation.*` services and a
   canonical `reveal` preset (`[data-lumina-anim="reveal"]`); on boot it
   conditionally enqueues the entry + reduced-motion CSS guard via the Phase-7
   AssetLoader.

## Consequences

- Animation is opt-in, declarative, and gated — reduced-motion users get
  static content with zero JS animation work.
- Payload is code-split: the animation entry is ~3.5 KB; GSAP/Lenis/Three
  chunks load only when the corresponding features are actually used.
- No page-specific animation ships; components consume presets in Phase 11.
- Performance budgets are enforced in one place (`Breaking`) and mirrored in
  the TS runtime.
