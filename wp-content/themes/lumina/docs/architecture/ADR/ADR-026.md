# ADR-026 — Rebrand to Lumina: namespace, handle, and contract renames

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 16 (Safe Rebranding)

## Context

Phase 16 rebrands the framework from Phantom to Lumina as a fully standalone
theme. The public identifier surface (namespace, prefixes, handles, CSS
variables) carried the old brand and had to change to `Lumina` everywhere —
while preserving functional parity with the frozen v0.14.0 baseline.

## Decision

1. **Namespace root:** `Phantom\Core\` → `Lumina\Core\` (PSR-4 → `app/`),
   including all `use` statements, FQCNs, and config provider references.
   Composer package renamed `phantom/phantom-core` → `lumina/lumina`.
2. **Global prefix:** `phantom_` → `lumina_` (functions, options, hooks),
   `phantom-` → `lumina-` (asset handles, CSS classes, data attributes).
3. **Design token CSS variables:** `--phantom-*` → `--lumina-*`. This is a
   contract-level rename: `API_FREEZE.md` and `CONTRACT_FREEZE.md` are
   updated to the Lumina surface (ADR-029-style freeze refresh).
4. **Domain events:** `phantom_core:*` → `lumina_core:*`.
5. **Text domain:** `phantom` → `lumina`; env file `lumina.env.json`.
6. **Version bump:** `0.14.0` → `1.0.0` (major — namespace + contract
   renames are breaking). `API_LEVEL` 1 → 2.
7. **Scope discipline:** 783 of 794 scanned source files changed; zero
   references to the old identifiers remain in the shipped theme (grep-zero
   gate). Build artifacts and vendor code were excluded; the Composer
   autoloader is regenerated by CI.

## Consequences

- Every smoke suite updated to the Lumina identifiers passes 100%
  (14 suites, 425+ assertions).
- The integrity gate is replaced by the Lumina self-integrity gate
  (`bin/verify-lumina-integrity.sh`).
- Consumers of the pre-1.0 namespace must migrate — this is exactly why the
  major bump exists.
