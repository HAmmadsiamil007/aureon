# ADR-020 — Phase 9 WooCommerce Bridge

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 9 (WooCommerce Bridge)

## Context

WooCommerce is the site's commerce layer and the most template-invasive
plugin. Phantom must isolate it fully: product/cart/checkout/account/order
data read through public WC APIs only, official hooks preserved (never
removed; re-emitted where Phantom output replaces a template), HPOS-safe
order reads, and WooCommerce Blocks left untouched. ADR-007 (bridges are
capability adapters) extends here with deeper data adapters.

## Decision

1. **Facade:** `Woo\WooBridge` extends the Phase 8 `Bridges\Bridge` contract
   (slug `woocommerce`, capabilities product/cart/checkout/account/order/
   hooks/hpos/blocks_safe). Enabled when `class_exists( 'WooCommerce' )`;
   version via `WC_VERSION`.
2. **Adapters** (`Woo\Data`): `ProductAdapter` (id, name, price, image,
   gallery, rating, stock, status, URLs, descriptions), `CartAdapter` (items,
   totals, count, currency, URLs), `CheckoutAdapter` (fields schema + order
   id from session), `AccountAdapter` (nav, pages, current user),
   `OrderAdapter` — HPOS-safe, reads exclusively through `wc_get_order()`.
3. **Hook preservation:** `Woo\Hooks\HookPreservation` holds the canonical
   30-hook table (plan §Phase 9) + `woocommerce_account_*` wildcard; `audit()`
   reports registered callbacks, `re_emit()` fires a hook only when it has
   callbacks (guarded). Phantom never removes a WC hook.
4. **Blocks compatibility:** Phantom never replaces WooCommerce Blocks;
   legacy template overrides are opt-in (`woo.enable` config, default
   `false`) and the bridge ships with `use_legacy_templates()` false.
5. **Static analysis:** WooCommerce is a dev-time unknown; minimal
   analysis-only stubs (`tests/stubs/woocommerce-stubs.php`) declare the
   exact public API surface used, wired into PHPStan (bootstrapFiles) and
   Psalm (`<stubs>`). Runtime guards (`class_exists`/`function_exists`)
   remain the source of truth — absent WC → inert defaults, never throws.
6. **Wiring:** `Woo\WooServiceProvider` binds `woo.*` adapters + `woo.bridge`
   (lazy singleton). Passive — no hooks installed, nothing overridden.

## Consequences

- Commerce data is reachable through one typed facade with safe WP-free
  defaults and zero cost when WC is absent.
- HPOS switch produces identical bridge output (single read path).
- Blocks shops render native markup — Phantom never hijacks them.
- PHPStan/Psalm verify the glue against declared public APIs without a live
  WC install or vendor stubs package.
