# ADR-022 — Phase 11 Frontend Component Library

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 11 (Frontend Component Library)

## Context

Phases 4–10 built the backend framework: a render engine, a component
registry, a template system, an asset pipeline, plugin bridges, a
WooCommerce bridge, and an animation engine. Phantom still ships no frontend
UI. Phase 11 turns the registry into a reusable, token-driven component
library — every visual element assembled from registered components that
consume the existing architecture instead of bypassing it (plan §Phase 11).

## Decision

1. **Catalog:** a single canonical `app/Components/config/components.json`
   defining **78 components** (shell, navigation, hero/banner, commerce,
   cart/checkout, content/interactive, blog/footer, states) with name,
   renderer view, version, data schema, variants, slots, and deps. The Phase-5
   JSON discovery seeds the existing `Registry` unchanged — no new registry.
2. **Templates:** every component is a `templates/components/{slug}.php`
   view rendered by the Phase-4 `PhpTemplateEngine`. Templates receive only a
   `ViewContext` (`$view`); every field passes through `e()`/`attr()`/`url()`.
   **No component calls WordPress functions or touches globals** — WP-free CLI
   parity is a hard requirement (verified by smoke-phase11).
3. **Styles:** one `assets-src/scss/_components.scss` layer. Every value is a
   `var(--phantom-*)` design token (ADR-003) — no hardcoded colors, spacing,
   typography, radius, shadow, or motion. Dark mode inherits the
   `[data-phantom-theme="dark"]` token remap. Reduced-motion is respected.
4. **Behavior:** `assets-src/ts/components.ts` — a vanilla, delegated,
   progressive-enhancement entry (tabs WAI-ARIA, modal/popup with focus
   management, dismissible banners, counters, back-to-top, toggle panels,
   sticky-add-to-cart). Keyboard-accessible, aria-aware, reduced-motion-gated.
   It is a **separate Vite entry** (like `animation`), code-split and
   conditionally enqueued only when the registry is non-empty.
5. **Wiring:** `ComponentsServiceProvider::boot()` enqueues the behaviors
   entry + token stylesheet via the Phase-7 `AssetLoader` only when the
   registry has components (zero cost when unused). Slots materialize child
   components (footer → footer-columns + copyright, hero → button, …).
6. **Consumption rules:** components never render themselves; they are always
   driven by the Registry, fed by Data adapters / ViewModels upstream. No
   page contains hardcoded business logic.

## Consequences

- 78 reusable, configurable, documented, independently testable components
  with consistent escaping, a11y, tokens, and animation hooks
  (`data-phantom-anim`, `data-phantom-*`).
- The component layer adds no runtime PHP dependencies; the JS behaviors
  entry is ~4.5 KB and only loads when components are registered.
- Templates (Phase 12) can be assembled entirely from these components — no
  duplicated markup.
- WooCommerce/GP/WordPress remain untouched; everything integrates through
  the Phase-4 renderer and Phase-7 loader.
