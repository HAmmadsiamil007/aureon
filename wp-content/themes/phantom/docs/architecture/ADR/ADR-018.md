# ADR-018 — Phase 7 Asset Pipeline

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 7 (Asset Pipeline)

## Context

The framework has no modern build pipeline or runtime asset loader. The plan
(§Phase 7) requires SCSS → CSS + TS/ESM → JS compilation (Vite), a manifest
consumed by a runtime loader, cache busting via hashed filenames, dev-server
(HMR) support, font loading, lazy/deferred delivery, and static emission of
the Phase-3 design tokens — all without touching GeneratePress.

## Decision

1. **Build:** `vite.config.js` (Phase 0 skeleton, expanded) defines two entries
   (`assets-src/ts/main.ts`, `assets-src/scss/main.scss`) with
   `manifest: true` → `assets/dist` (Vite 6 writes `.vite/manifest.json`;
   the reader probes both locations).
2. **Static token emission (ADR-005):** `bin/build-tokens.php` boots the
   real kernel WP-free and writes the token repository CSS
   (`:root` + `[data-phantom-theme]`) into `assets-src/scss/_tokens.scss`
   (generated, prettier-ignored, committed so CI's asset job needs no PHP).
   `main.scss` `@use`s it — the shipped CSS carries every `--phantom-*` var.
3. **Runtime loader** (`Assets\\AssetLoader`): `resolve()`/`asset_url()` pick
   the dev-server URL (`PHANTOM_VITE_ACTIVE=1`, port from `PHANTOM_VITE_PORT`)
   or the manifest's hashed file, or fall back to the raw source. `css()`,
   `js()`, `font_face()` are WordPress-guarded; enqueue versions use the
   `BuildFingerprint` (md5 of the manifest) so the browser cache busts per
   build.
4. **Manifest internals:** `ManifestReader` (memoized, suffix-tolerant),
   `Pipeline\\Entries` (isEntry index), `Pipeline\\DepsResolver` (transitive
   import closure, cycle-safe) — all WP-free testable.
5. **Markup policy:** `Markup::defer_all()` (runtime same-origin defer) and
   `Markup::preload_critical_css()` (preload link, escaped).
6. **Images:** `Image::srcset()` uses public WP APIs when present (empty map
   WP-free); `Image::build_srcset()` is the pure, tested builder.
7. **Delivery:** `AssetLoader::css()/js()` are called by templates/plugins;
   config `assets.enqueue` (default empty) optionally auto-enqueues on
   `wp_enqueue_scripts`. Everything is hashed (cache-busted) and deferred.

## Consequences

- Production ships one hashed CSS + one deferred JS; dev gets HMR with zero
  config beyond two env vars (ADR-011).
- Tokens are compile-time in production — no per-request CSS generation.
- `assets/dist` is gitignored; the manifest drives all URLs (no magic paths).
- Animation/commerce entries code-split onto this pipeline in Phases 10/9.
