# ADR-024 — Phase 13 Performance Engineering

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 13 (Performance Engineering)

## Context

Phase 13 optimizes the entire framework toward the Core Web Vitals targets
(LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.10) without touching locked subsystems
(Render Engine, Registry, Template System, Woo Bridge, Animation). The plan
(§Phase 13) defines four public performance APIs that must exist and be
individually testable, plus a subsystem provider and config wiring.

## Decision

1. **`Performance\Budget`** — an immutable value object holding the Core Web
   Vitals + payload budgets (LCP, CLS, INP, JS KB, CSS KB, server ms, query
   count). Defaults match the plan targets and are overridable via
   `performance.budgets` config. Every limit is exposed via a stable accessor
   and `to_array()` so the logger and any CI gate evaluate the same numbers.
2. **`Performance\BudgetLogger`** — records timings/metrics against the budget
   and reports pass/fail per key. WP-free safe: the default transport keeps an
   in-memory log that smoke tests assert against; a PSR-3 `Log` hookup can be
   injected without changing the contract.
3. **`Performance\QueryGuard`** — WordPress query introspection guard,
   active only when `performance.query_guard` is enabled (debug-only). It
   counts queries on `pre_get_posts` via `wp_count_queries()`-style hooks
   without modifying any query — it warns, never blocks. Default off so
   production pays zero cost.
4. **`Performance\Lazy`** — tiny deferred-execution utility: queues callables
   to run at `shutdown` (when WordPress is present) or immediately when
   flushing without WordPress, ensuring no late work ever blocks first paint.
5. **`Performance\CachePurger`** — central cache-purge helper. It fires the
   namespaced `phantom_core:cache_purged` action so caching plugins and the
   Render Cache can flush; the `functions.php` bridge passes through
   `wp_cache_flush()` when available. WP-free safe (checks `function_exists`).
6. **Provider + config:** `PerformanceServiceProvider` registers the five
   services and wires the QueryGuard to `pre_get_posts` only when active.
   Config gains a `performance` block; feature gate `performance` is on.
   No locked subsystem is modified.

## Consequences

- All four plan APIs exist, are unit-testable without WordPress, and are
  verified by `bin/smoke-phase13.php` (41 assertions, WP-free).
- Production defaults cost nothing: query guard is off, lazy queue is no-op
  without registered callables, budget logging is in-memory until a transport
  is injected.
- Cache invalidation is centralized behind one namespaced action — plugin and
  render caches flush consistently without coupling to any cache backend.
- GeneratePress, GP Premium, WooCommerce, and WordPress Core remain
  untouched; the integrity gate still passes 473/473.
