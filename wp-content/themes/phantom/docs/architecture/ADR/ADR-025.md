# ADR-025 — Phase 14 Accessibility Engineering

- **Status:** Accepted
- **Date:** 2026-08-04
- **Phase:** 14 (Accessibility Engineering)

## Context

Phase 14 targets WCAG 2.2 AA with no exceptions, without touching locked
subsystems or redesigning UI. The plan (§Phase 14) defines a static HTML
audit (`A11y\Checker::run(string $html): array`), a skip link, and a dialog
focus-trap contract. Everything must be WP-free verifiable in CI and
integrate through the existing provider pattern.

## Decision

1. **`A11y\Checker`** — a pure string analyzer that audits rendered HTML
   deterministically: heading hierarchy (exactly one h1, no skipped levels),
   landmarks (header/nav/main/footer), image alt attributes, form label
   coverage (for/id or wrapping label, aria-label/labelledby accepted),
   interactive accessible names (links/buttons), focus hygiene (no positive
   tabindex), and dialog focusability (role="dialog" must carry
   tabindex="-1"). Because it is WP-free, CI audits every component/template
   render without a browser, and the Phase-14 smoke suite asserts real
   pass/fail findings.
2. **`A11y\SkipLink`** — static markup builder for the first-focusable skip
   link (`screen-reader-text phantom-skip-link` → `#main`), with WP-first /
   PHP-fallback escaping (`esc_attr`/`esc_html` vs `htmlspecialchars`).
   `A11yServiceProvider::boot()` emits it at the top of the body via
   `wp_body_open` priority 1 when WordPress is present.
3. **`A11y\DialogManager`** — the server-side contract + validation seam for
   accessible dialogs: declares the required attribute set (`role="dialog"`,
   `aria-modal="true"`, `tabindex="-1"`, `aria-labelledby`) and validates any
   rendered dialog element against it. The runtime focus trap remains in the
   Phase-11 behaviors entry (`components.ts`); this class guarantees the
   markup side and feeds CI.
4. **Provider + config:** `A11yServiceProvider` binds `a11y.checker`,
   `a11y.skip_link`, `a11y.dialog`; feature gate `accessibility` is on. No
   component, template, or locked subsystem was modified — the audit is a
   verification layer, not a rewrite.

## Consequences

- All Phase 14 plan APIs exist and are WP-free unit-testable, verified by
  `bin/smoke-phase14.php` (36 assertions).
- Skip link ships on every page via the standard `wp_body_open` hook — no
  theme file modification, GP/GP Premium untouched.
- Dialog accessibility is enforced in two places that agree: the PHP contract
  (`DialogManager::validate()`) and the JS focus trap (`components.ts`),
  closing the loop CI can verify.
- No UI redesign, no business logic changes, no vendor modification; the
  integrity gate remains 473/473.
