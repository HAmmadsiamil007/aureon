### The key rule to remember

**You are not making the frontend dynamic again every time you redesign it.**

You are doing this once:

```text id="8o7yml"
PREMIUM FRONTEND
        ↓
AUREON CONTRACT
        ↓
WORDPRESS / WOOCOMMERCE
```

Then future work is:

```text id="mrk9d3"
CHANGE DESIGN
        ↓
KEEP CONTRACT
        ↓
KEEP DATA
        ↓
KEEP FEATURES
```

That is the architecture you want for a reusable client-production system. Your existing architecture documentation follows the same principle of keeping presentation, bridge/data translation, and protected Core responsibilities separate. 

And because your latest redesign process already demonstrated that a presentation change can introduce regressions such as script-order problems, this plan deliberately requires **targeted regression after each slice and full regression before generating the new release candidate**.
